# 실제 FSR4 exact ISA의 dot4 실행량

근거는 exact_warm_profile의 DXIL 경계·loop, 실제 gfx1030 ISA와 GPU pass timestamp다. bytecode에 있는 fp8 이름과 달리 실행 명령은 signed INT8 dot4다. timing 표는 warm40/timed200 진단 표본이다.

관측 기준 처리량은 **91.679754 TOPS**다. wave32 synthetic 프로브와 FSR의 wave64 명령 경로는 조건이 다르다. 아래 기준시간은 dot4만 이 속도로 처리했을 때의 계산값이며 물리적 최저시간을 보증하지 않는다.

8 integer ops/dot4 = 4 multiply + 4 accumulate add. pass7/8은 144×8+64×32+128×16=5248회, pass9는 여기에64×32를 더한7296회다. branch 전에 제외되는 경계 lane은 유효 실행량에서 뺐다. 부분 wave의 남는 issue 비용은 이 값에 들어가지 않는다.

합계는 dot4가 있는 network12개와 post만 포함한다. prepass·exposure·padding·dispatch 사이의 비용은 별도다.
- 1920x1080 Native: 3,396,556,800 dot4, 27.172454 GOP, dot 기준 0.296384 ms, 해당 pass 진단 중앙값 합 0.534260 ms.
- 3840x2160 Native: 13,586,227,200 dot4, 108.689818 GOP, dot 기준 1.185538 ms, 해당 pass 진단 중앙값 합 2.183520 ms.

1080p와4K에서 논리 실행량은 정확히4배다. ISA 자원·static 명령수는 대응 pass별로 같다. 실제 시간의4배 이탈은 입력 크기, cache/메모리, 점유, clock과 dispatch 고정비를 포함하므로 이 표만으로 특정 원인을 확정하지 않는다.

재현: `python3 analysis/parse_isa.py` 뒤 `python3 analysis/build_dot_workload.py`. 상세 원자료는 DOT4_WORKLOAD.json, exact_profile_isa.json, MEMORY_MODEL.json, 각 pass의 원래/복원 disassembly를 함께 본다.
